# EcoHousingExporter

Server-side Eco mod stub for Eco Housing V0.2.

The goal of this mod is to expose the exact data consumed by the web app from a live Eco server. The app should not scrape local server files and should not depend on unstable vanilla web endpoints for economy data.

## API Contract

The mod must expose:

```http
GET /api/v1/eco-housing/status
GET /api/v1/eco-housing/data
GET /api/v1/eco-housing/economy
```

### `/status`

Returns server/exporter metadata:

```json
{
  "serverName": "Eco Server",
  "ecoVersion": "0.11.x",
  "exporterVersion": "0.2.0",
  "generatedAt": "2026-06-09T00:00:00.000Z",
  "endpoints": ["/api/v1/eco-housing/status", "/api/v1/eco-housing/data", "/api/v1/eco-housing/economy"],
  "warnings": []
}
```

### `/data`

Returns the same schema as `outputs/eco-data.json` generated by the local extractor:

- `housing`
- `items`
- `recipes`
- `skills`
- `roomCategories`
- `roomTiers`
- `worldObjects`
- `occupancy`
- `housingEquivalenceGroups`
- `meta`

The data must represent the live server rules, including installed mods.

### `/economy`

Returns a normalized market snapshot:

```json
{
  "fetchedAt": "2026-06-09T00:00:00.000Z",
  "currencies": ["Credits"],
  "listings": [
    {
      "itemClass": "HewnTableItem",
      "quantity": 5,
      "price": 12.5,
      "currency": "Credits",
      "storeName": "Carpentry Store",
      "seller": "Player"
    }
  ],
  "warnings": []
}
```

## Implementation Notes

- This directory is intentionally a stub until the Eco ModKit references are wired in.
- Keep the wire format stable; the web app validates the minimum schema and displays exporter warnings.
- Prefer exposing already-normalized item class names (`HewnTableItem`) so the web app can match market data to `eco-data.json`.
- If a server cannot expose a field, return a warning instead of omitting the entire endpoint.
